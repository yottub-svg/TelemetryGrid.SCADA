Профиль нагрузки: поток 1 500 пакетов телеметрии/сек с кольцевым буфером и окном агрегации в реальном времени.

## 01. Разработка клиентской части на Windows Forms

**Индивидуальный вариант:** потокобезопасный реалтайм-монитор на `System.Threading.Channels`.

Реализовать приём высокочастотного потока данных в фоновом `Task` через `BoundedChannel` и пакетный слив (batch flush каждые 100 мс) в UI-контролы.

Компоненты: `Channel<T>.CreateBounded`, DoubleBuffered Panel, `SynchronizationContext / BeginInvoke`, `PeriodicTimer`.

Граничные случаи: при всплеске 2 000 событий/сек применяется `DropOldest`; закрытие формы во время активного потока корректно завершает Producer/Consumer без `ObjectDisposedException`.

Критерий приёмки: задержка от поступления пакета до отрисовки не более 120 мс при 1 500 msg/sec, загрузка CPU UI не более 15%.

## 02. Разработка UI/UX C#-приложения

**Индивидуальный вариант:** клавиатурная доступность, `TabOrder` и экранные дикторы (UI Automation).

Спроектировать полную навигацию без мыши, логичный `TabIndex`, мнемонические горячие клавиши и корректные `AccessibleName / AccessibleRole`.

Компоненты: AccessibleObject Overrides, TabIndex Matrix, FocusVisualStyle Custom Draw, Shortcut Hint Overlay (Alt Hold).

Граничные случаи: Tab проходит по форме в визуальном порядке без застревания в скрытых панелях; у каждого графического индикатора и кнопки-иконки заполнен `AccessibleName`.

Критерий приёмки: 100% сценариев формы выполняются только с клавиатуры, проверка через Inspect.exe / Accessibility Insights.

## 03. Интеграция клиента и сервера через REST API

**Индивидуальный вариант:** потоковый стриминг больших выгрузок (`IAsyncEnumerable / NDJSON`).

Реализовать серверный endpoint, отдающий поток записей через `IAsyncEnumerable<T>`, и клиент с `HttpCompletionOption.ResponseHeadersRead`.

Компоненты: `IAsyncEnumerable<T> Endpoint`, `ResponseHeadersRead`, System.Text.Json Streaming, передача `CancellationToken`.

Граничные случаи: отмена на клиенте мгновенно прерывает курсор на сервере; выгрузка 200 000 записей начинается с первой секунды без полной буферизации в памяти API.

Критерий приёмки: TTFB не более 100 мс, потребление RAM API при выгрузке 200k строк не более 40 МБ.

## 04. Аутентификация и авторизация в ASP.NET Core

**Индивидуальный вариант:** динамический RBAC + Permission Claims с мгновенным отзывом прав.

Разделить роли и гранулярные разрешения, реализовать кэшируемый middleware проверки `SecurityStamp`, чтобы блокировка пользователя действовала до истечения JWT.

Компоненты: `PermissionAuthorizationPolicyProvider`, `SecurityStampValidationMiddleware`, `IMemoryCache` Stamp Cache, `HasPermissionAttribute`.

Граничные случаи: уволенный пользователь с действующим JWT получает 401 на следующем запросе; изменение прав роли не требует перекомпиляции.

Критерий приёмки: блокировка аккаунта вступает в силу не позднее 5 секунд при TTL кэша штампа 5 секунд.

## 05. Модульное тестирование на C#

**Индивидуальный вариант:** тестирование асинхронных потоков, `Channel<T>` и `CancellationToken`.

Написать детерминированные тесты Producer/Consumer телеметрии с проверкой отмены, переполнения буфера и отсутствия deadlock.

Компоненты: xUnit Async Tests, TaskCompletionSource Barriers, bounded policies `Channel<T>`, Verify Snapshot Testing.

Граничные случаи: зависший Consumer доказывает, что `DropOldest` сохраняет новые критические события; отмена в середине пачки освобождает ресурсы.

Критерий приёмки: 100 последовательных прогонов без падений, время выполнения не более 2 секунд.

## 06. Интеграционное тестирование и отладка C#

**Индивидуальный вариант:** интеграция Timescale/PostgreSQL и фоновых `HostedService` в тестовом хосте.

Проверить полный цикл POST телеметрии → Channel → BackgroundService → пакетная вставка в БД → GET агрегата через `WebApplicationFactory`.

Компоненты: WebApplicationFactory, Testcontainers.PostgreSql, Awaitility / Polling Helper, Batch Insert Verification.

Граничные случаи: переполнение пакета или битый датчик не теряет валидные записи; Graceful Shutdown сбрасывает остаток канала в БД.

Критерий приёмки: 100% сохранность подтверждённых пакетов при Graceful Shutdown, время набора тестов не более 12 секунд.

## 07. Интеграционное тестирование и отладка C#

**Индивидуальный вариант:** профилирование CPU-горячих точек (`dotnet-trace + Speedscope Flamegraph`).

Снять трассировку под потоком 1 500 сообщений/сек, найти дорогую рефлексию/LINQ-аллокации на Flamegraph и оптимизировать через `Span<T>` и кэширование.

Компоненты: `dotnet-trace`, Speedscope / PerfView, `ReadOnlySpan<char>`, allocation-free hot path.

Граничные случаи: заменить `string.Split` на Span-парсинг без временных массивов; исключить повторную компиляцию Regex внутри цикла.

Критерий приёмки: снижение времени CPU на горячем пути минимум в 3 раза и аллокаций Gen0 минимум на 70%.

## 08. Подготовка задания на внедрение информационной системы на C#

**Индивидуальный вариант:** ТЗ на внедрение диспетчерской телеметрии на действующем производстве.

Подготовить ТЗ с подключением промышленных контроллеров (OPC UA / Modbus TCP), требованиями к ЭМС, резервированием АРМ диспетчера и обучением смен.

Компоненты: схема информационных потоков АСУ ТП, спецификация протоколов опроса, регламент параллельной опытной эксплуатации, инструкция оператора.

Граничные случаи: описать поведение при зависании одного PLC без влияния на остальные цеха; зафиксировать допустимое отставание тревоги не более 1 секунды.

Критерий приёмки: чётко разграничить ответственность ИТ-отдела, подрядчика и службы КИПиА.

## 09. Разработка плана и стратегии внедрения системы

**Индивидуальный вариант:** сменный ввод АСУ ТП (Shift-by-Shift Rollout) без потери контроля над цехом.

Разработать план внедрения: параллельный мониторинг «Только чтение» две смены, обучение четырёх бригад диспетчеров и поочерёдное подключение цехов.

Компоненты: график волн 1–3, план обучения сменных мастеров, критерии Go/No-Go, резервный канал связи.

Граничные случаи: ночная смена сталкивается с неизвестной ошибкой интерфейса; требуется регламент поддержки L1/L2 и возврат на старую консоль без перезапуска PLC.

Критерий приёмки: простой телеметрии при переключении равен 0 секунд за счёт параллельного запуска.

## 10. Подготовка серверного окружения для C#-приложения

**Индивидуальный вариант:** автономный локальный сервер цеха (Docker Compose + TimescaleDB + Healthchecks).

Собрать production-ready multi-stage Dockerfile с non-root chiseled .NET image и `docker-compose.yml` с restart policy, healthchecks и volume-бэкапами.

Компоненты: chiseled Dockerfile, compose-файл, cron-скрипт `pg_dump`, Docker logging driver `json-file` с `max-size`.

Граничные случаи: образ API distroless/chiseled без bash/curl; лимиты памяти и CPU не позволяют всплеску телеметрии положить хост.

Критерий приёмки: образ API не более 120 МБ, восстановление из бэкапа проверено тестовым скриптом.

## 11. Настройка сети и прав пользователей C#-системы

**Индивидуальный вариант:** air-gapped технологическая сеть (VLAN АСУ ТП) и однонаправленный шлюз.

Спроектировать сетевую политику OT/IT: запрет прямой маршрутизации, доступ только через буферный API-прокси.

Компоненты: OT/IT Firewall Ruleset, MAC/Port Security Binding, Read-Only Telemetry Role, Windows Firewall GPO Policy.

Граничные случаи: офисный клиент читает агрегаты только через прокси и не имеет маршрута до PLC; NetBIOS/LLMNR/SMB запрещены.

Критерий приёмки: полная сетевая изоляция контроллеров и 0 открытых административных портов в сторону офисной сети.

## 12. Публикация и установка Windows Forms-приложения

**Индивидуальный вариант:** WiX Toolset v4/v5 (MSI) с тихой установкой по GPO и Custom Actions.

Создать MSI-инсталлятор с параметрами командной строки (`API_URL=...`), ярлыками, регистрацией протокола и чистым удалением.

Компоненты: WiX v4/v5 `Package.wxs`, `msiexec /qn API_URL=...`, Registry App Config Injection, MajorUpgrade Clean Uninstall.

Граничные случаи: при MajorUpgrade сохранить или мигрировать пользовательский конфиг; после `msiexec /x` удалить ярлыки и временные бинарники.

Критерий приёмки: тихая установка проходит на чистой Windows VM с кодом выхода 0 и подробным `install.log`.

## Общие обязательные требования сайта

- Разделять UI, Application и Domain; не помещать SQL/HTTP и бизнес-логику в code-behind.
- Все длительные операции выполнять асинхронно с `CancellationToken`, не блокировать UI.
- Освобождать ресурсы и отписываться от событий в `Dispose`.
- Не использовать `.Result`/`.Wait()`, отключение cross-thread проверок, сырые stack trace в Production и ручную конкатенацию SQL.
- Для сдачи каждого модуля подготовить исходный код, тесты/доказательства сценариев, README и артефакты из чек-листа конкретного варианта.
