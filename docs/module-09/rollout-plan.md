# Shift-by-Shift Rollout Plan — TelemetryGrid.SCADA

Цель: подключить цеха по сменам без потери контроля и с нулевым простоем телеметрии.

## Календарный план

| Этап | Срок | Объём | Результат |
|---|---:|---|---|
| Подготовка | T-10…T-5 | инвентаризация PLC, каналов, ACL и резервов | подписан baseline |
| Shadow | T-4…T-3 | только чтение, 2 смены | сверка тревог со старой консолью |
| Волна 1 | T-2 | один некритичный участок | подтверждены latency и rollback |
| Волна 2 | T+1 | два участка средней критичности | обучение 2 бригад и ночной контроль |
| Волна 3 | T+3 | оставшиеся участки | переход на новую консоль после Go |
| Гиперподдержка | T+4…T+10 | все смены | ежедневный разбор инцидентов |

## Варианты стратегии

Используется комбинация Shadow → Canary → Shift-by-Shift. В режиме Shadow новая система только читает данные. В Canary одна ограниченная зона переводится на новый монитор, старая консоль остаётся готовой к немедленному возврату.

## RACI

| Работа | ИТ | КИПиА | Подрядчик | Начальник смены | Диспетчер |
|---|---|---|---|---|---|
| Firewall/VLAN | R/A | C | C | I | I |
| Карта PLC и порогов | C | R/A | C | C | I |
| Развёртывание ПО | R | C | R | I | I |
| Go/No-Go | C | C | C | R/A | C |
| Операционная работа | C | C | I | A | R |
| Откат | R | R | R | A | C |

R — выполняет, A — несёт ответственность, C — консультирует, I — информируется.

## Обучение четырёх бригад

Каждая бригада проходит 90-минутное занятие: обзор экранов, подтверждение тревоги, поиск истории, действия при потере связи и возврат на старую консоль. Практическая часть завершается двумя учебными тревогами и проверкой по чек-листу.

## Go/No-Go-гейты

Go возможен только при выполнении всех условий: задержка тревоги ≤ 1 секунды, heartbeat всех критичных PLC, отсутствие дублей, доступность резервного канала и АРМ, успешный тест отката, обученная смена и заполненный журнал ПМИ.

No-Go: необъяснимая потеря событий, открытый маршрут IT → PLC, непроверенный rollback, недоступный дежурный инженер или незавершённое обучение.

## Резервный канал и непрерывность

Основной и резервный каналы проверяются до каждой волны. При обрыве основной линии OT-шлюз переключается на резервный, а при недоступности обоих сохраняет очередь локально. Управление технологией остаётся на старой консоли до восстановления.
